# 🔧 Исправление ошибки кодировки базы данных

## ❌ Проблема

```
Database initialization failed: 'utf-8' codec can't decode byte 0xc2 in position 61: invalid continuation byte
```

## ✅ Решение

### Вариант 1: Переустановить переменные окружения

Проблема обычно возникает из-за специальных символов в пароле или неправильной кодировки при сохранении.

1. **Пересоздайте .env файл:**
   ```cmd
   set_db_env.bat
   ```
   
2. **Используйте только ASCII символы в пароле:**
   - Используйте буквы, цифры и основные символы: `!@#$%^&*`
   - Избегайте специальных символов типа: `©`, `®`, `€`, и т.д.

3. **Перезапустите API:**
   ```cmd
   run.bat
   ```

---

### Вариант 2: Установить переменные вручную в PowerShell

```powershell
$env:DB_HOST="localhost"
$env:DB_NAME="fraud_detection"
$env:DB_USER="postgres"
$env:DB_PASSWORD="your_password_here"
```

Затем запустите API в том же окне PowerShell:
```powershell
.\venv\Scripts\Activate.ps1
python -m uvicorn src.fastapi_service:app --host 0.0.0.0 --port 8000 --reload
```

---

### Вариант 3: Проверить .env файл

Если файл `.env` существует, проверьте его содержимое:

```powershell
Get-Content .env -Encoding UTF8
```

Убедитесь что:
- Файл сохранен в UTF-8
- Пароль не содержит проблемных символов
- Нет лишних пробелов вокруг `=`

## 💡 Рекомендации

1. **Используйте простой пароль:**
   - Только буквы и цифры
   - Без специальных символов Unicode

2. **Проверьте .env файл:**
   - Сохраняйте в UTF-8
   - Убедитесь что нет BOM (Byte Order Mark)

3. **Если проблема сохраняется:**
   - Работайте без БД (API работает без неё)
   - Или используйте переменные окружения в PowerShell вместо .env
